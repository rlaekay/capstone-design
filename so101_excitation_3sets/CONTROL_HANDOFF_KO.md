# SCServo 제어 PC에 전달할 데이터 계약

## 이 패키지가 제공하는 것

오프라인 관절 목표와 시뮬레이션 비교 기록입니다. SCServo_Linux 라이브러리, USB 드라이버, 실제 모터 제어 프로그램은 포함하지 않습니다.
실제 제어 프로그램은 아래 계약에 맞춰 CSV를 읽고, 해당 로봇의 보정값으로 변환해 기존 SDK에 목표 위치를 전달해야 합니다.

## 명령 열과 좌표

CSV: `time_s,reference_qpos0_rad,...,reference_qpos5_rad`

| 열 | 관절 |
|---|---|
| reference_qpos0_rad | shoulder_pan |
| reference_qpos1_rad | shoulder_lift |
| reference_qpos2_rad | elbow_flex |
| reference_qpos3_rad | wrist_flex |
| reference_qpos4_rad | wrist_roll |
| reference_qpos5_rad | gripper |

- 값은 MuJoCo 관절 좌표계의 rad입니다. 엔코더 tick, 도(deg), LeRobot 정규화 값이 아닙니다.
- 6번째 관절의 1.2 rad는 로봇 모델의 그리퍼 회전각이지 그리퍼 폭(mm)이 아닙니다.
- 관절 열 순서는 모터 ID 순서라는 뜻이 아닙니다.
- time_s는 각 파일 시작부터의 초입니다. 명시된 timestamp를 사용하며 행 번호를 시간으로 간주하지 않습니다.
- 학습 명령은 0~12초, 100 Hz, 양 끝점을 포함한 1201행입니다. 전체 경로는 준비 구간의 샘플 간격이 정확히 10 ms가 아닐 수 있습니다.

## 필요한 실제 로봇 보정

`calibration.example.json`을 별도 복사하여 실제 측정값으로 채우세요. 비어 있는 값은 의도적이며 기본값이 아닙니다.
필수: 관절별 servo_id, MuJoCo 0 rad에 대응하는 raw 위치, 회전 방향, 실제 사용 가능한 raw 최소/최대, 포트/baudrate.
한 회전 4096 tick인 해당 엔코더 설정을 확인했다면 변환 형태는 다음과 같습니다.

`raw_goal = round(zero_tick + direction * q_rad * ticks_per_radian)`

여기서 direction은 +1/-1, ticks_per_radian은 4096/(2*pi)입니다. 실제 모터의 동작 모드/영점 처리와 일치해야 합니다.
범위를 벗어나면 멈추고 보정을 확인해야 합니다. `%4096`으로 감거나 clamp하여 원래 경로를 바꾸지 마세요.
동적 궤적의 SDK speed/acceleration 설정이 별도의 시간 프로파일을 만들면 주어진 목표 시간과 달라질 수 있으므로 제어 PC에서 그 설정을 명시해야 합니다.

## 실행과 기록 흐름

1. 현재 읽은 실제 관절각을 모델 좌표로 변환하고 전체 경로의 첫 자세와 비교합니다. CSV를 시작한다고 첫 자세로 즉시 점프시키지 않습니다. 임의 현재 자세에서 첫 자세까지의 경로는 이 패키지에 포함되지 않습니다.
2. 준비가 된 뒤 전체 reference.csv를 단조 증가 시계 기준으로 보간하여 목표를 보냅니다. 각 행마다 sleep(0.01)을 누적하는 방식은 시간 지연을 누적시킬 수 있습니다.
3. SDK가 지원하는 다중 모터 쓰기 기능을 사용해 같은 시점의 관절 목표를 함께 전달하고, 전송/읽기 시각을 각각 기록합니다. 특정 SDK 함수명이나 모터 설정은 이 문서에서 가정하지 않습니다.
4. `config.json`의 training_window_s는 전체 명령 시작 기준의 학습 시작/끝입니다. 학습 구간만 쓸 때는 실제 로봇이 그 구간의 첫 자세에 도달해 정지한 상태여야 합니다.
5. 시작/완료 시각, 실제 전송 목표, 읽은 실제 위치/속도/load/current/전압/온도, 드론 IMU의 원본 시각과 수신 시각을 저장합니다. 계획 시각과 실제 전송 시각은 구분합니다.
6. 통신 실패/추종 오차/정지 요청을 처리하는 방식은 실제 제어 프로그램에 있어야 합니다. 패키지 재생기는 하드웨어 안전 정지 기능이 아닙니다.

시뮬레이션 가속도는 world XYZ의 병진가속도입니다. 원시 IMU specific force와 직접 비교하지 말고 좌표계/중력 처리를 맞춥니다.
실제에서 속도를 줄여 수행했다면 시뮬레이션 가속도와 그대로 같다고 볼 수 없습니다. 시간 배율을 s배 늘리면 동일 기하 경로의 속도는 1/s, 가속도는 1/s²로 달라집니다.
